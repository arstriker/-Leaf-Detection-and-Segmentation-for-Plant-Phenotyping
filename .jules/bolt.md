## 2025-02-12 - Redundant Image Conversions
**Learning:** In the `Automated Leaf Detection and Phenotyping` app, PIL images were being converted to NumPy arrays for some tasks, and then those NumPy arrays were being passed into PyTorch and YOLOv8 models. Both PyTorch and YOLOv8 natively handle PIL images and implicitly convert NumPy arrays back to PIL format internally, creating a redundant double-conversion overhead that wastes CPU cycles and memory.
**Action:** Always ensure that PIL images are preserved and passed directly to deep learning models like YOLOv8 and PyTorch to avoid unnecessary double-conversions when possible.
## 2025-02-13 - Redundant Intermediate Array Allocation with bitwise_and
**Learning:** Using `cv2.bitwise_and(image, image, mask=mask)` to extract color channels solely for feature calculation forces the allocation of a full-size intermediate array before discarding the background zeros. In memory-constrained scenarios or high-throughput pipelines, this is inefficient compared to applying direct boolean indexing (`image[mask > 0]`) to the original image array, which extracts only the necessary pixels.
**Action:** When calculating statistics or features on masked regions, use direct boolean indexing rather than creating intermediate full-size masked arrays unless the full array is strictly required for visualization or subsequent spatial operations.
